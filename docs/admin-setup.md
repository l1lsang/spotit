# 관리자·신고·문의

`/admin`을 직접 입력하면 별도의 관리자 비밀번호 화면이 열립니다. 일반 사용자 메뉴에 관리자 링크는 없습니다. 관리자 인증은 일반 Firebase 로그인과 분리되어 일반 계정 로그인 상태를 바꾸지 않습니다.

## 포함 기능

- 통계: 전체 유저, 게시 중인 핀, 채팅방, 미처리 신고·문의·자동 검토, 최근 7일 가입·핀, 이용 정지 계정 수.
- 유저 관리: 닉네임·사용자 이름은 접두어 검색, 이메일·UID는 정확히 일치하는 값 검색. 검색어를 비우면 가입일이 없는 기존 계정까지 전체 목록을 페이지 단위로 표시합니다. 상세에서 정지·해제 사유를 기록할 수 있습니다.
- 접수 관리: 유형·상태 필터, 페이지 단위 조회, 신고 당시 서버 원본 증거, 내부 메모, 사용자에게 공개할 답변, 처리 상태 변경.
- 핀 숨김·복구: 원본 핀을 비공개 관리 컬렉션으로 이동합니다. 지도·피드·직접 상세 URL에서 조회할 수 없고 작성자가 같은 ID로 다시 등록할 수 없습니다. 관리자가 복구할 수 있습니다.
- 사용자 신고: 핀 상세의 핀·작성자 신고, 사람 목록의 유저 신고, 채팅방 및 개별 메시지 신고. 1:1 채팅에는 상대 유저 신고도 있습니다.
- 문의: 프로필 → 문의·신고 내역(`/support`)에서 문의를 보내고 본인의 접수 상태와 답변을 확인합니다.

## 서버 설정과 배포

프런트엔드 빌드만 배포하면 관리자 로그인 및 접수 API는 작동하지 않습니다. 아래 서버 설정과 규칙을 함께 적용해야 합니다. 이번 구현 작업에서는 운영 배포를 실행하지 않았습니다.

1. Functions 의존성을 설치합니다: `npm --prefix functions install`.
2. `firebase functions:secrets:set SPOTIT_ADMIN_PASSWORD`를 실행하고 값으로 요청한 비밀번호 **quokka**를 입력합니다. 비밀번호를 `VITE_` 환경변수로 만들면 브라우저 번들에 공개되므로 서버 Secret Manager에만 설정합니다.
3. `firebase deploy --only firestore:rules,firestore:indexes`로 규칙과 인덱스를 적용합니다. 인덱스가 준비된 후 다음 단계로 진행합니다.
4. `firebase deploy --only functions`로 서버 함수를 배포합니다. 기존 푸시 알림 함수도 유지됩니다. Firebase Functions 배포가 가능한 프로젝트 요금제와 권한이 필요합니다.
5. `npm run build` 후 기존 프런트엔드 배포 방식으로 `dist`를 배포합니다. Functions 지역은 `us-central1`입니다. 기존 Vercel SPA rewrite가 `/admin` 직접 접속을 지원합니다.

배포 전 현재 규칙의 백업을 보관하고, 배포 후 일반 사용자 로그인·팔로우·핀 등록·댓글·채팅 흐름도 점검하세요. 기준 규칙은 루트의 `firestore.rules`입니다. 기존에 `match /{document=**} { allow read, write: if true; }`가 있으면 **그대로 둔 채 관리자 컬렉션에 false 규칙을 추가해서는 보호되지 않습니다.** 루트 규칙 전체를 적용해야 합니다. 기존 공개 규칙에서는 새 신고·세션 컬렉션도 노출될 수 있습니다.

관리자 API는 매 요청마다 서버 세션을 확인합니다. 세션은 4시간 후 만료하며 로그아웃하면 서버에서도 폐기됩니다. 토큰은 브라우저 탭의 sessionStorage에 보관하고 서버에는 해시만 저장합니다. 로그인 요청은 IP당 15분에 8회, 신고·문의는 계정당 시간당 10회로 제한합니다. 같은 계정의 같은 대상·메시지 신고는 중복 접수하지 않습니다. 문의는 요청 ID로 재전송 중복을 막습니다.

계정 정지 시 Firestore 게이트를 먼저 설정한 뒤 Firebase Auth 계정을 비활성화하고 새로고침 토큰을 폐기합니다. 이 때문에 기존 ID 토큰으로도 핀·채팅 데이터에 접근할 수 없습니다. 인증 상태 동기화가 실패하면 차단 상태를 유지하며 같은 작업을 재시도할 수 있습니다. 영구 계정 삭제는 제공하지 않습니다.

## 로컬 검증

Java 21 이상, Firebase CLI, Node 및 `functions/node_modules`가 필요합니다.

1. 커밋되지 않는 `functions/.secret.local`에 `SPOTIT_ADMIN_PASSWORD=quokka`를 넣습니다. 현재 작업 공간에는 설정했습니다.
2. `firebase emulators:start --config firebase.emulators.json --project demo-spotit`를 실행합니다.
3. 다른 터미널에서 `npm run test:moderation`을 실행합니다. 실제 Auth·Firestore·Functions 에뮬레이터 및 운영용 Firestore 규칙을 검증합니다. `npm run test:profiles`도 같은 규칙에서 검증할 수 있습니다.
4. UI 검증 시 `VITE_USE_FIREBASE_EMULATORS=true`와 `VITE_FIREBASE_PROJECT_ID=demo-spotit` 등 **데모 프로젝트** 설정으로 Vite를 실행합니다. 운영 프로젝트에 테스트 데이터를 쓰지 마세요.

## 부적절한 핀을 거르는 방식

현재 구현은 신규·수정 핀의 제목·내용·장소명을 서버에서 검사합니다. 불법 촬영물 거래, 일부 불법 거래 문구, 여러 링크 도배가 감지되면 `자동 검토` 접수가 생깁니다. 같은 내용으로 반복 이벤트가 발생해도 중복 검토를 만들지 않습니다. 키워드만으로 오판할 수 있으므로 자동 삭제하거나 차단하지 않습니다. 기존 핀 전체를 소급 검사하지는 않습니다.

사진은 현재 관리자가 신고 증거에서 직접 확인합니다. 다음 단계로 [Cloud Vision SafeSearch](https://docs.cloud.google.com/vision/docs/detecting-safe-search)의 성인·폭력 가능성 분석을 연결할 수 있습니다. 이미지 모델에도 오탐이 있으므로 높은 위험도는 임시 보류하고, 애매한 결과는 관리자가 판정하는 방식이 적합합니다. 등록 전 완전한 검수는 게시 요청을 서버로 옮겨 검사 완료 전 `pending` 상태로 보관하고, 승인 후에만 `posts`로 공개해야 합니다. 현재 검사 트리거는 등록 **후** 실행되므로 게시 전 차단 기능은 아닙니다.

신고 수만으로 자동 삭제하면 악의적인 집단 신고에 취약하므로 현재는 관리자 검토 근거로만 사용합니다. 신고 당시 필요한 증거를 보관하며, 방 전체 신고는 최근 20개 메시지, 개별 메시지 신고는 선택한 메시지만 전달합니다. 다른 채팅방을 함께 읽지 않습니다.

핀 숨김은 Firestore의 원본 핀을 제거합니다. 이미 저장·공유된 Storage 다운로드 URL과 이용자가 다운로드한 사진까지 회수하지는 않습니다. 이미지 자체의 접근 폐기와 보관 기간에 따른 증거·감사 로그·만료 세션 정리는 별도 운영 정책으로 추가할 수 있습니다.

설정 참고: [Firebase 서버 시크릿](https://firebase.google.com/docs/functions/config-env), [Functions 에뮬레이터](https://firebase.google.com/docs/emulator-suite/connect_functions).
