# 성능 개선 (2026-09-11)

## 적용한 변경

- 피드: 전체 작성자 기록을 읽고 자르던 방식에서 서버 정렬·커서·limit 조회로 변경. 한 화면은 24개 후보 기록이며, 팔로우 작성자 5명씩 묶어 조회하고 최대 4개 요청만 동시에 실행한다. 다음 페이지 확인용으로 쿼리별 1개를 추가로 읽는다. 같은 작성 시각의 기록도 문서 ID로 정렬하므로 페이지 사이에 누락되지 않는다.
- 피드 위치·반경 변경: 이미 불러온 기록에서 필터링하므로 같은 게시물을 다시 읽지 않는다. 이전 기록은 ‘이전 기록 더 보기’로 계속 조회한다. 검색 범위가 현재 불러온 기록임을 화면에 명시했다.
- 조회 재사용: 피드·팔로우 목록·사람 목록은 30초, 프로필은 60초 동안 메모리에 보관한다. 진행 중인 같은 요청도 공유한다. 실패한 요청은 캐시하지 않는다. 로그인 계정 변경과 게시물/팔로우/프로필 수정, 명시적 새로고침은 캐시를 초기화한다. 프로필 앨범의 접근 여부는 최신 프로필과 Firestore 규칙으로 계속 확인한다.
- 지도 장소 검색: 같은 검색어·좌표·지도 제공자 요청을 5분간 재사용한다. 지도 드래그는 기존에도 Firestore 쿼리를 호출하지 않았다.
- 리스너: 화면 근처 카드만 좋아요 상태와 반응 수를 구독한다. 탭을 숨기면 카드 반응 구독을 해제한다. 댓글을 펼친 동안에는 스레드를 유지하며, 답글 수가 명시적으로 0인 댓글은 답글 조회·구독을 생략한다. 예전 데이터에 답글 수 필드가 없으면 기존 방식으로 읽는다.
- 새 사진: 최대 1,600px WebP 압축, 게시물 목록용 480px 썸네일, 프로필 사진 최대 384px. GIF와 지원하지 않는 이미지 디코더는 원본을 유지한다. 썸네일이 없는 기존 게시물은 기존 URL을 사용한다. 사진 삭제·순서 변경 시 썸네일 배열도 함께 정렬한다.
- 로그인: 완성된 기존 프로필을 트랜잭션에서 읽었으면 추가 getDoc을 생략하고, 이미 받은 프로필로 화면을 먼저 표시한다.

## 배포 순서

새 피드 쿼리는 `firestore.indexes.json`의 posts 복합 인덱스 2개가 필요하다. 인덱스를 먼저 배포하고 Firebase 콘솔에서 READY 상태를 확인한 뒤 프런트엔드를 배포한다.

```powershell
firebase.cmd deploy --only firestore:indexes
npm.cmd run build
```

이 작업에서는 운영 인덱스·사이트를 배포하지 않았다. 에뮬레이터는 복합 인덱스의 존재를 강제하지 않으므로 로컬 통과가 운영 인덱스 준비를 대신하지 않는다.

## 범위와 남은 개선

실제 운영 응답 시간이나 다운로드 바이트의 전후 비교는 아직 측정하지 않았다. 코드와 에뮬레이터에서 요청 수·페이지 순서·권한·회귀 동작을 확인했다.

- 기존 업로드 사진은 자동 변환되지 않는다. 과거 사진까지 줄이려면 별도 썸네일 생성/백필 작업이 필요하다.
- 주변 기록은 시간순 페이지를 읽은 뒤 거리로 필터링한다. 공간 인덱스/지오해시 검색을 도입하면 먼 장소의 후보를 읽는 비용도 줄일 수 있다. 최근 페이지에 근처 장소가 없으면 ‘더 보기’로 이전 기록을 확인할 수 있다.
- 사람 찾기는 부분 문자열 검색을 유지하기 위해 첫 요청에서 사용자 목록 전체를 읽는다. 이를 없애려면 서버 검색과 페이지네이션 설계가 필요하다.
- 프로필 앨범, 그룹 핀, 좋아요 모음, 채팅 과거 메시지와 답글이 있는 댓글은 아직 전체 조회/구독 경로가 남아 있다. 추가 페이지네이션과 공유 구독으로 개선할 수 있다.
- Firestore 위치는 변경하지 않았다. 메모리 캐시는 새로고침 시 없어지며 다른 기기의 변경은 해당 캐시 만료까지 늦게 보일 수 있다.

## 검증

`npm.cmd run build`, `npm.cmd run lint`, `npm.cmd run test:performance`와 기존 지도·이미지 편집·피드 검색·프로필 테스트를 실행한다. `npm.cmd run test:post-interactions`는 격리된 Firebase 에뮬레이터에서 묶음 조회, 커서 동률, 캐시 재사용, 팔로우 해제, 접근 거부, 댓글/답글 및 좋아요 실시간 동작을 검증한다.
