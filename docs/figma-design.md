# 스팟잇 Figma 디자인

[Figma 파일 열기](https://www.figma.com/design/EjpFbZdXpHKNf9AtgoAYpX?node-id=2-2)

2026-09-08 현재 웹앱의 로그인 전 화면을 편집 가능한 Figma 레이어로 변환했습니다.
PC는 1440px, 모바일은 390px이며, 같은 페이지의 PC/모바일 화면이 나란히 배치되어 있습니다.

| 화면 | PC 노드 | 모바일 노드 |
| --- | --- | --- |
| 시작 | 2:2 | 19:2 |
| 로그인 | 14:2 | 8:2 |
| 회원가입 1단계 | 23:2 | 10:2 |
| 지도 | 15:2 | 20:2 |
| 피드 | 17:2 | 21:2 |

텍스트, 버튼 모양, 벡터 아이콘, 배경과 이미지 레이어를 편집할 수 있습니다.
원본 CSS의 반복 배경 중 첫 화면의 58px 격자는 별도 벡터로 복원했습니다.

## 반영된 상태

- 로그인 전 화면입니다. 개인 프로필, 채팅, 알림, 기록 상세 등 로그인 후 데이터는 포함하지 않았습니다.
- 지도는 로컬 브라우저의 카카오맵 로딩 오류 상태가 반영되어 있습니다.
- 피드는 로그인 전 빈 상태이며 위치 권한 안내가 포함됩니다.
- 웹 시스템 글꼴은 Figma의 SF Pro와 한글 대체 글꼴로 변환됩니다. 피드의 `10km` 표시에 지원되지 않는 Arial Black은 Arimo Bold로 교체했습니다. 브라우저와 글자 폭이 다를 수 있습니다.
- 웹앱 기능은 실행되지 않는 정적 디자인입니다. 재사용 컴포넌트 라이브러리나 프로토타입 연결은 생성하지 않았습니다.

## 검증

10개 화면 모두 실제 텍스트와 하위 레이어가 있는지 확인한 뒤 이름과 위치를 정리했습니다.
첫 화면과 모바일 로그인은 Figma 렌더링 이미지도 확인했습니다.
남은 화면의 최종 이미지 검수는 Figma Starter 도구 호출 한도로 완료하지 못했습니다.

`index.html`의 Figma 캡처 도우미는 개발 모드에서 `#figmacapture=`가 명시된 경우에만 실행됩니다.
React 화면과 글꼴이 로딩된 후 캡처 스크립트를 불러옵니다. 일반 접속 시 실행되지 않으며,
`npm run build`가 성공했고 프로덕션 HTML에 캡처 스크립트 URL이 남지 않는 것을 확인했습니다.
